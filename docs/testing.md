# Практика тестирования Bank Lab

Все операции работают только с вымышленными деньгами внутри стенда.

## Демо-пользователи

После `make up` доступны:

| Email | Пароль | Пользователь |
|---|---|---|
| alice@banklab.test | Lab-demo-478! | Алия |
| bob@banklab.test | Lab-demo-478! | Данияр |

Номер карты Данияра: `9900000000000003`. У Алии две карты, у Данияра одна.
При первом создании демо-данных общий баланс Алии — 125 000 ₸, включая
5 000 ₸ на депозите. Повторный `seed_demo` сохраняет существующие данные.

## Проверки вручную

1. Зарегистрировать нового пользователя. Счета, депозит и история пустые.
2. Попробовать пустые поля, неправильный email, простой пароль, повторный email.
3. Создать две карты. Третий счёт отклоняется и через API.
4. Пополнить свой счёт на 1000 ₸. Суммы 0, -1, 0.001 и более 1 000 000 не принимаются.
5. Перевести 125.50 ₸ между своими картами. Суммарный баланс не меняется.
6. Перевести на карту Данияра; войти под ним и проверить зачисление и историю.
7. Попробовать несуществующую карту, перевод самому на ту же карту, нехватку средств.
8. Открыть депозит. Второй активный депозит отклоняется сервером.
9. Пополнить депозит со счёта; закрыть его с возвратом денег; открыть новый.
10. Отключить сеть / остановить backend, обновить экран. Проверить сообщение об ошибке.
11. Выйти из аккаунта. Его токен больше не должен работать в API.

## API

Swagger: http://localhost:8000/api/docs/

Сначала вызвать `/api/auth/login/`, затем в Authorize передать `Token <token>`
(точный формат поля показан в Swagger). Либо заголовок запроса:

```text
Authorization: Token <token>
```

Денежные суммы передавать строками, например `"125.50"`. Валюта KZT.
Для перевода обязательны `account_id`, `card_number`, `amount`, `request_id` (UUID).
Повторить тот же перевод с тем же `request_id`: списание должно произойти один раз.
Изменить сумму с тем же `request_id`: сервер вернёт 400.
Другой `request_id` означает новую операцию.

История возвращает до 50 записей и курсор `next`. Следующая страница:
`/api/history/?before=<next>`.

в учебной базе для анализа.

## Charles и серверные логи

Debug-сборка использует HTTP по адресу `http://10.0.2.2:8000/api` из Android
Emulator. Это адрес компьютера из стандартного Android-эмулятора. Для Charles
можно настроить прокси Android на `10.0.2.2:8888`, если Charles слушает порт 8888.
Настройку прокси, доверие сертификату и HTTPS-перехват выполняем отдельным этапом.

HTTP здесь служит локальной учебной работе. Разрешение cleartext задано только
в debug manifest. Для release-сборки нужен HTTPS-сервер и соответствующий API_URL.
Токен хранится только в памяти: после перезапуска приложения нужно войти заново.
В первой версии один токен на пользователя; выход завершает все его сессии.

```sh
docker compose logs -f backend
```

API пишет JSON-логи с `request_id`, HTTP-методом, путём, статусом и длительностью.
Ответ содержит `X-Request-ID`, по которому можно найти запрос. Пароли, токены,
номера карт и тела запросов не логируются. Это основа для следующего подключения Loki.
Grafana и Loki пока не включены в Compose.
